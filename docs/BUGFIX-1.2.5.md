# CodeMentor 1.2.5 会话卡死修复与模型 IO 隔离

发布日期：2026-08-24。

## 修复内容

### 上下文采集异常不再卡死会话

评审与修改验证都先在后台非阻塞 ReadAction 中读取代码上下文，成功后再回到 EDT 继续。此前该计算若抛出意外异常（PSI 损坏、意外运行时错误等），成功回调不会触发，异常也没有任何消费方：

- 评审链：侧栏停在空状态，无任何错误提示；手动管线状态残留，还会持续抑制后续保存触发的评审。
- 验证链：会话卡在 VERIFYING，验证按钮被禁用，用户只能重新发起一次完整评审才能恢复。

1.2.5 在计算内部捕获意外异常（取消与 `ProcessCanceledException` 仍正常传播），立即在 EDT 上把会话转入可重试的失败分支：评审显示"读取代码上下文失败，请重试"，验证显示同义提示并恢复按钮。真实异常同时带请求上下文写入日志。被新请求取代的失败采集只清理自己的管线状态。

### 模型请求迁移到独立线程池

模型请求是长达 120 秒的阻塞 IO。此前它们与平台短时任务共用 `AppExecutorUtil` 共享池，评审、验证、追问、小练习并发时可占满该池，影响 IDE 中其他使用同一池的功能。1.2.5 为模型请求建立上限 4 的专用有界池，并在 IDE 关闭时随应用服务释放。

配套修复：

- 设置页连接测试复用同一个 `HttpClient`。Java 17 的 `HttpClient` 无法显式关闭，旧版每次点击"测试连接"都会遗留 selector 线程。
- 侧栏面板 `dispose()` 改用构造时缓存的 `ReviewSession` 引用退订。项目关闭时面板销毁与项目服务销毁的顺序不受插件控制，旧版在 `dispose()` 里做服务查找可能抛 `AlreadyDisposedException` 导致退订未执行。
- 各处 `CompletableFuture.cancel(true)` 改为 `cancel(false)`：该参数对 CompletableFuture 被忽略，任务并不会被中断；新写法如实表达"放弃结果"，行为不变。
- 重复知识点提醒按相同参数缓存 45 秒。旧版每次评审成功都全量读取并聚合学习历史（最多 2×4MB），并推迟同一线程上的学习事件落盘；清除历史会使缓存立即失效。
