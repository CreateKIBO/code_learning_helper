# CodeMentor 1.2.0 体验升级说明

发布日期：2026-08-22

CodeMentor 1.2.0 把侧栏从“展示模型结果”调整为一条可恢复的个人学习路径：选择评审或解释，先核对证据并思考，再完成一个最小步骤、主动自测，最后按需查看讲解、示例、验证或练习。插件依旧不会自动修改用户源码，也不会执行项目命令或代写完整项目。

## 1. 首次使用与空状态

首次打开 CodeMentor 时，空状态直接提供三个入口：

- “评审当前代码”：复用 `Alt+M` 对选中代码或当前 Java 方法进行教学式评审；
- “解释当前代码”：复用 `Alt+Shift+M`，帮助理解执行流程、职责和关键概念；
- “配置模型…”：直接打开 `Settings / Preferences → Tools → CodeMentor`。

空状态同时明确模型只提供证据、提示和自测，不会把建议自动写入编辑器。首次真正需要发送未缓存上下文时，仍执行 1.1.0 建立的项目 × 端点授权和脱敏预览流程。

## 2. 请求状态、取消与错误恢复

评审或解释进入模型请求后提供“取消本次请求”；追问等待时原按钮变为“取消追问”；小练习生成中提供“取消生成”，失败后可原位重试。修改验证没有单独取消入口，但新评审、同一文件继续变化或会话 reset 会取消它。评审失败页同时提供“重试当前操作”和“打开设置…”。

取消使用现有协调器的 generation、requestId 和可取消 Future 机制，让迟到回调不能覆盖新会话。取消只能尽力停止本地等待和 HTTP 工作，不能撤回模型服务已经收到的数据。

## 3. 更紧凑的侧栏和稳定阅读位置

顶部保留“生成小练习”、当前模式的重新请求和“更多…”；以下次要操作收纳到更多菜单：

- 查看发送预览；
- 查看学习统计；
- 导出复习清单；
- 隐私与数据；
- 打开 CodeMentor 设置。

建议正文使用可自动换行的原生文本区；参考代码和练习起始代码使用等宽、可独立滚动的代码区。这样既适应窄 Tool Window，也不会把长代码强行折行。

在同一个 `learningReviewId` 内，讲解/示例展开状态保存在 `ReviewSession`，Tool Window 重绘后恢复滚动位置。点击反馈、发起或完成验证、追问以及逐条查看练习提示时，不会丢失当前阅读进度。新评审或会话 reset 会清空这些视图状态，避免旧卡片状态串到新结果。

## 4. 从结果列表到学习路径

### 4.1 整体总结

模型评审和解释现在解析为不可变 `ReviewResult`：

```text
ReviewResult
├── summary
└── suggestions（最多 3 条）
```

`summary` 会和建议一起进入缓存与会话。评审模式合法返回空建议数组时，侧栏仍展示“未发现需要优先处理的问题”和整体评价；解释模式必须至少返回一个中性的理解要点。summary 中明显声称已经编译、运行或测试成功的内容会被本地拒绝。

### 4.2 每条建议的渐进步骤

建议卡按以下顺序组织：

1. 代码依据：模型引用的当前分析目标源码片段；
2. 先想一想：先给方向，不立即揭示完整答案；
3. 先做这一步 / 理解路径：`nextStep` 只要求学习者完成一个最小动作；
4. 完成标准 / 学会的标准：用于判断是否达到目标；
5. 理解原因：按需展开完整讲解；
6. 自测一下：`selfCheckQuestion` 用于主动回忆；
7. 查看参考：最后才展示可选短示例，且明确不是唯一答案。

评审模式显示“明确问题、可能风险、设计取舍”，完整方法评审支持“我改好了，验证”；解释模式显示“理解要点”，不把理解内容包装成错误，也不要求用户修改代码。

## 5. 证据来源约束

1.2.0 要求模型为每条建议从实际 `JAVA_CODE` 数据块复制空白等价的连续 8～160 个字符作为 evidence，不允许改写非空白字符、添加省略号或引用不可见文件。响应返回后，`EvidenceGroundingValidator` 在本地：

1. 使用与本次请求相同的脱敏 `modelContext`，并单独建立脱敏目标源码 allowlist；
2. 去除证据两端成对引号并折叠空白；
3. 检查每条规范化证据是否同时存在于发送上下文和目标源码中，不能只引用 package、imports、诊断摘要、技术标签或截断标记；修改验证还必须引用当前版本的目标源码；
4. 任一建议无法核对时拒绝整次结构化结果，交由既有有限重试处理。

该检查不发送额外数据，也不证明模型结论一定正确；它只保证展示的代码依据来自模型实际可见的目标代码。最终判断仍应结合源码、编译、测试和运行结果。

## 6. 模式与教学级别

“评审我的写法”和“解释这段代码”使用不同 system prompt 与界面语义；解释结果在本地必须至少包含一个理解要点且统一使用中性的 `MEDIUM` 置信度。教学级别会进一步调整侧重点：

| 教学级别 | 评审侧重点 | 解释侧重点 |
|----------|------------|------------|
| 初学 | 术语、语言规则、基本类型和控制流程 | 沿输入、关键分支和输出建立直观心智模型 |
| 进阶 | 可读性、异常处理、测试、面向对象设计和 Java 特性 | 对象协作、状态变化、异常传播和关键语言机制 |
| JavaWeb | HTTP、Controller/Service/Repository 分层、校验、事务、持久化与安全边界 | 请求经过当前层的路径，以及注解、依赖和职责边界 |

设置页使用中文级别名称。追问请求也携带当前教学级别和 JavaWeb 角色，使同一个快捷问题能保持适合当前学习阶段的表达，但不会增加项目代码范围。

## 7. 超长上下文的首尾保留

模型上下文总预算仍为 16,000 个字符。目标代码可以完整放入时，package、imports、类型摘要、引用字段、IDE 诊断和技术标签按优先级填充剩余预算。

若目标代码本身超过预算，1.2.0 会保留约三分之二首部与三分之一尾部，并在中间插入“目标代码中段已按字符预算截断”标记。提示词同时告诉模型只能判断可见片段，不得断言截断区域中的校验、事务、异常处理或其他逻辑不存在。

## 8. 追问问答的生命周期

“继续追问…”提供三个预设问题，也可输入最多 2,000 个字符的自定义问题。等待期间按钮变为“取消追问”；卡片在请求中、成功或失败时都会显示最近一次问题。回答在本地必须非空、不超过 8,000 字符、以自测问题结束，且不能明显声称已执行编译/运行/测试；不合格时最多自动重试一次。

隐私和持久化边界保持严格：

- 每条建议只保留最近一次追问状态；新问题会替换该建议的旧问题/回答；
- 问题和回答只存于当前项目 `ReviewSession` 的内存 map；
- 新评审、session reset 或项目关闭后消失；
- 不写入 `learning-events.jsonl`，不进入学习统计，也不进入 Markdown 复习导出；
- 发起追问仍需通过当前项目 × 端点授权、统一出站守卫和当前评审身份检查。

## 9. 逐条练习提示与弱知识点过滤

生成的小练习先展示知识点、任务、限制、起始代码和完成标准，不再一次性展示所有 hints。学习者只有点击“查看下一条提示（n/总数）”时才展开下一条。解析器要求至少两条互不重复的渐进提示、非空完成标准，并校验返回知识点与目标一致。

本地历史先按 NFKC、大小写、空白、标点和少量保守的 Java/JavaWeb 同义标签合并知识点名称，并按带可靠 `reviewId` 的不同评审次数计数；同一次评审中的重复建议只算一次。无法可靠恢复评审范围的旧记录仍可统计和导出，但不驱动重复薄弱点。选择薄弱知识点时排除三类建议：

- 修改验证结果为 `RESOLVED`；
- 用户反馈为 `FALSE_POSITIVE`（误报）。
- 模型置信度为 `LOW`。

其他尚未验证、部分解决或仍未解决且置信度不低的知识点继续按不同评审次数参与排序。提醒要求至少 3 次，练习优先选择至少 2 次；没有历史目标时只回退到当前有效建议。异步历史读取结束和 fallback 模型响应落地前都会重新检查当前建议，等待期间变为误报、已解决或验证中的旧练习不会展示。请求只发送知识点、次数、教学级别和 JavaWeb 角色。

## 10. 修改验证与请求优先级

修改验证仅对完整方法开放。评审时创建的活体 `RangeMarker` 会随方法前的普通增删移动，定位点固定在外层方法声明开头并校验当前 PSI 方法覆盖整个锚点，避免误落入匿名类/局部类方法；修改原方法签名/名称仍可定位，整段删除则拒绝。整篇文件替换或磁盘重载会让锚点直接失效，不能把相同偏移处的新方法误认成原目标。选中片段仍可评审和解释，但不显示验证入口。

因为 imports、引用字段、类注解和诊断也可能进入模型上下文，同一 Java 文件发生任意编辑都会保守地让当前结果过期，并同步使 generation 或 pending 身份失效；已排队的旧回调不能进入缓存、会话或历史。验证是否“发生变化”比较实际发送的脱敏上下文，而不只比较方法体；一次验证完成后若继续编辑同一文件，旧的已解决/部分解决/未解决结论会立即恢复为未验证，避免把上一文档版本的结论留在卡片上。

缓存回放保留第一次评审的学习关联 ID，不会把同一结果重复计入历史。手动评审从规则和 PSI 采集阶段就高于延迟保存评审；保存回调不会抢占用户刚刚主动发起的学习操作。“清除全部本地学习记录”会先清空所有已打开项目的 session/缓存并取消在途任务，再删除全局历史。

## 11. 延续的隐私与安全基线

1.2.0 不扩大 1.1.0 的发送授权或持久化范围，继续保留：

- 项目 × 规范化端点授权；
- 默认 HTTPS 与显式 loopback-only HTTP；
- 统一 `OutboundRequestGuard`；
- 预览与真实评审共享的 `MaskedReviewPayload`；
- PasswordSafe API Key；
- 有界 HTTP/JSON、容量 50 的内存缓存和有界轮转历史；
- 项目外文件和敏感/排除文件拒绝；
- 完整 UUID、generation 与迟到响应守卫。

完整说明见 [PRIVACY.md](../PRIVACY.md) 和 [ARCHITECTURE.md](ARCHITECTURE.md)。
